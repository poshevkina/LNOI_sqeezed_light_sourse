# Как запускать расчёты и смотреть результаты

[Техническая карта кода и форматов для ИИ](agent-workflow.md).

Работа разделена на получение полей COMSOL, численные исследования и просмотр отчётов. Для повторного построения графиков достаточно сохранённого отчёта и компактных случаев SPDC. Для нового подбора ветвей нужны также карты полей.

```text
сценарий Python или конфигурация JSON + модель MPH + таблицы материалов
    └─ linbo3 → COMSOL → CSV и манифесты + локальные карты полей
         └─ studies → отбор ветвей → фиты по ω → SPDC и число Шмидта
              ├─ общий кэш компактных случаев
              └─ отчёт исследования → ноутбук просмотра
```

## Запуск исследования

Параметры серии 0,4–0,7 мкм задаются в [сценарии Python](../studies/fit_effect_04_07.py). Запускайте из корня репозитория:

```powershell
python -m studies.fit_effect_04_07 --dry-run
python -m studies.fit_effect_04_07
python -m studies.fit_effect_04_07 --solve
```

`--dry-run` показывает модель, точки и состояние кэша. Обычный запуск читает готовые карты и при необходимости восстанавливает ссылки и CSV из кэша. `--solve` разрешает досчитать недостающие пары, после чего сценарий строит отчёт. В ноутбуке для этой серии выберите `STUDY = "fit-effect-w04-w07"`.

Остальные сценарии запускаются через `python -m studies.fit_effect`, `python -m studies.unclassified`, `python -m studies.spatial_single` и `python -m studies.pulse_series`. `--comsol-run <имя>` закрепляет источник, `--comsol-dir <путь>` указывает готовую выгрузку вне стандартного каталога, `--results-root` задаёт каталог отчётов и кэша. Уменьшение `--points` меняет частотную сетку SPDC. Сценарии можно запускать по полному пути к файлу из другой рабочей папки.

Команда `python -m linbo3 --config run_config_comsol_04_07.json` доступна для прежних JSON-конфигураций и использует тот же адаптер одиночного волновода.

## Подключение модели

В [linbo3/comsol_models](../linbo3/comsol_models) каждая модель лежит в одной папке с кодом, который знает её теги, параметры и правила выгрузки.

- [`single/`](../linbo3/comsol_models/single) содержит `god_save_me_compact.mph`, адаптер и вызовы решателя для диапазонов PUMP и IS.
- [`coupled/`](../linbo3/comsol_models/coupled) содержит исходную и рабочую 2D-модели, адаптер одноточечного расчёта и построитель рабочего шаблона.
- [`coupler_3d/`](../linbo3/comsol_models/coupler_3d) содержит исходную 3D-модель, построитель рабочей копии и адаптер. [Запуск прямого 3D-ответвителя с модами из 2D](../linbo3/comsol_models/coupler_3d/README.md).
- [`materials/`](../linbo3/comsol_models/materials) содержит общие внешние таблицы материалов. Если указать собственный MPH вне папки его адаптера, Python ищет таблицы рядом с ним.

Сценарии исследований остаются в [`studies/`](../studies). Результаты и поля лежат в `results/` и `field_maps/`.

[Общий сеанс](../linbo3/comsol_session.py) управляет MPh и журналом, [исполнитель](../linbo3/comsol_jobs.py) записывает статус и блокирует одновременные запуски. Адаптер передаёт исполнителю задачи и функцию сохранения. Для двух модовых моделей общий [кэш полей](../linbo3/comsol_models/cache.py) поддерживает CSV и NPZ. Другой тип исследования может определить собственный формат выгрузки.

### Два соседних 2D-волновода

Из исходной локальной MPH один раз создаётся рабочая копия `coupled_waveguides_2d_clean.mph`:

```powershell
python -m linbo3.comsol_models.coupled.template "linbo3/comsol_models/coupled/coupled_waveguides_2d_original.mph"
python -m studies.coupled_modes --dry-run
python -m studies.coupled_modes --solve
```

Построитель сохраняет шаблон рядом с исходным файлом. В шаблоне сохранены геометрия, материалы,
граничные условия, настройки сетки и один шаг Mode Analysis. Построитель
удаляет Parametric Sweep, его задачу, прежние решения и связанные с ними
результаты, затем создаёт одну цепочку решателя и один dataset. Для шаблона в каталоге модели Python берёт `n_SiO2.txt` из общей папки `materials/`.

[Сценарий Python](../studies/coupled_modes.py) задаёт ширину 0,5 мкм,
длину волны 1550 нм и верхние зазоры 0,6–3,0 мкм с шагом 0,2 мкм.
COMSOL для каждого сочетания зазора и сдвига поиска решает отдельную точку.
`--dry-run` показывает кэш, обычный запуск строит отчёт по готовым данным,
`--solve` досчитывает недостающие точки. `--pilot` ограничивает серию
зазором 0,8 мкм и пишет отдельный пилотный отчёт.

В `results/studies/coupled-modes/` лежат карты полей, `candidates.csv`
с ID решений, `pairs.csv` с расщеплениями и длинами перекачки и
`verification.csv` со сравнением сеток. Сведения о недостающих точках
находятся в `coverage.csv`. `mesh_check_at_gap` отмечает прямое сравнение
на данном зазоре. Для остальных точек используется максимальное наблюдённое
изменение расщепления для той же поляризации. При расщеплении не больше
двух таких изменений точное значение длины перекачки не публикуется.

Оси поля идут в порядке `electric[компонента, y, x]`, координаты в мкм.
`x` поперёк пары, `y` перпендикулярна плёнке, `z` вдоль волноводов.
Метки even/odd относятся к векторному отражению, которое меняет знак
компоненты `Ex`. График показывает также относительную фазу доминирующей
компоненты в сердечниках. Цветовая шкала `|E|²` имеет общий максимум внутри
пары после нормировки интегралов полей. Кривые мощности применяют приближение
двух малопотерных мод прямого однородного ответвителя.

```python
import matplotlib.pyplot as plt
import numpy as np

from studies.coupled_modes import open_mode

# Зазор, сдвиг и ID берутся из candidates.csv.
profile = open_mode("results/studies/coupled-modes", gap_um=0.8,
                    shift=2.15, outer_solnum=0, solnum=5)
plt.pcolormesh(profile.x_um, profile.y_um,
               np.sum(abs(profile.electric)**2, axis=0), shading="nearest")
plt.gca().set_aspect("equal")
plt.xlabel("x, µm")
plt.ylabel("y, µm")
plt.colorbar(label=r"$|E|^2$")
plt.show()
```

Манифест фиксирует хеш MPH, внешних файлов и настройки поиска. Старые выгрузки
сохраняют свои ключи. Новый результат хранится в
`results/comsol/coupled-waveguides-2d/` отдельно от входов SPDC.

При контрольном сравнении на 1550 нм, ширине 0,5 мкм и зазоре 0,8 мкм
максимальная разность комплексных n_eff между исходной и чистой моделью
составила 8,9 × 10⁻¹⁶. Подпространства двух отсчитанных полей совпали
в пределах численной точности. Отдельно вычислены зазоры 0,8 и 1,0 мкм
из Python. Повтор использовал две готовые карты. Этот тест подтверждает
эквивалентность шаблона при сдвиге поиска 2,0. Направляемые пары TE₀/TM₀
для анализа перекачки отбираются отдельно.

Чтобы добавить модель, определите класс с путём к MPH и методами её расчёта. Опишите неизменяемые входы и их хеши, сформируйте задачи из параметров сценария и используйте общий сеанс и исполнитель. Если результат — таблица мод и поля на 2D-сетке, можно переиспользовать `ModalTask` и `run_modal`. Для своего формата задайте собственную функцию выгрузки и проверки готовых данных.

## Прямой 3D-ответвитель

[Руководство по 3D-модели](../linbo3/comsol_models/coupler_3d/README.md)
описывает имя локального MPH, передачу входных 2D-полей и режимы запуска.
Для двух поляризаций на 16 слоях при зазоре 0,8 мкм проверь список задач,
запусти расчёт или пересобери графики из готового кэша.

```powershell
python -m studies.coupler_3d_compare --dry-run
python -m studies.coupler_3d_compare --solve
python -m studies.coupler_3d_compare
```

Каждая поляризация сохраняется сразу в `field_maps/`. В папке случая
`comsol.log` показывает ход расчёта, `diagnostics.png` открывает обзор поля,
а `sections.npz` содержит массивы для Python. Сравнительный отчёт лежит в
`results/studies/coupler-3d-compare-g0p8-16layers/`. В `coverage.csv` видно,
какие решения готовы и у каких сохранено поле по всему объёму.

## Кэш полей COMSOL

[Адаптер одиночного волновода](../linbo3/comsol_models/single/model.py) формирует сетки и задачи «ширина × диапазон». [Точка входа JSON](../linbo3/pipeline.py) переводит прежнюю конфигурацию в вызов того же адаптера. Файлы одной карты хранятся в `field_maps/<подпись>/`, включая комплексные компоненты поля, исходные идентификаторы, параметры и журнал. CSV со значениями n_eff и JSON со ссылками на поля лежат в `results/comsol/<прогон>/`.

Манифест прогона охватывает весь набор ширин. Подпись карты строится для отдельной ширины и диапазона и учитывает точную сетку длин волн, модель, таблицы материалов, геометрию и параметры извлечения. Это позволяет переиспользовать карты при изменении списка ширин. Повтор той же команды после прерывания подбирает сохранённые карты и дополняет недостающие пары. По `status.json` видно состояние каждой пары. Оно становится `complete` после
записи карты, её манифеста и CSV. Пару с готовой картой можно восстановить,
даже если процесс прервался до записи CSV. При чтении сопоставляется SHA-256
поля в NPZ с манифестом. Параллельный запрос той же карты ждёт завершения её
записи, затем проверяет готовые файлы. Блокировка прогона защищает общий
`status.json` от одновременной записи двумя процессами.

## Кэш SPDC и отчёты

[Загрузка выгрузок](../linbo3/saved_modes.py) сверяет строки CSV с идентификаторами NPZ. [Отслеживание мод](../linbo3/modes.py) проверяет потери и перекрытие полей. Пространственные сценарии дополнительно используют [классификацию](../linbo3/mode_classification.py) для выбора TE/TM. При недостатке данных или неоднозначности смотрите `pairs.csv` или `spatial_diagnostics.csv` в соответствующем отчёте. PUMP-ранг задаётся отдельно для каждой ширины.

[Расчёт SPDC](../linbo3/spdc.py) использует входные ветви и полиномы по угловой частоте. [Ключ численного случая](../linbo3/case_cache.py) зависит от входных рядов и коэффициентов, параметров импульса и волновода, частотной сетки и версии расчёта. Имя исследования в ключ не входит. В `results/cases/` один NPZ на случай хранит число и веса Шмидта, период полинга, точные одномерные проекции полной сетки и карты превью до 129 × 129.

[Публикация отчёта](../linbo3/study_output.py) обновляет `results/studies/<имя>/` после успешного завершения. Уже готовые численные случаи остаются в общем кэше при прерывании. `summary.csv` содержит ключи случаев и относительные пути к NPZ. По отчёту и этим NPZ ноутбук открывает графики без COMSOL. Для повторной классификации и выбора ветвей понадобятся поля.

## Git и проверка

Модель одиночного волновода, таблицы материалов, сценарии, конфигурации, исходный код и документация версионируются. Исходная 2D-модель соседних волноводов и 3D-модель сейчас доступны в локальной копии. Локальные исходные файлы ответвителя, производные шаблоны и отчёты прогонов ответвителя исключены из Git. `field_maps/`, старые полные JSA в `jsa_full/` и временные каталоги публикации исключены из Git. Для публикации конкретного исследования выбирайте нужный отчёт и связанные компактные случаи. Стандартный PR с кодом не требует добавлять результаты локальных запусков. Прежние ноутбуки и совмещённая конфигурация описаны в [архиве](../legacy/README.md).

Тесты запускаются через `python -m unittest discover -s tests -p "test_*.py"`. Они используют синтетические поля и подменяют запуск решателя. Проверки охватывают продолжение прерванного расчёта, повторное использование SPDC, публикацию отчёта и преобразование старого формата.
