# Карта COMSOL и данных для ИИ

[Руководство для исследователя](workflow.md) описывает команды и файлы отчётов.

## Точки входа

- `studies.coupled_modes` планирует отдельные задачи по зазору и сдвигу
  поиска для 2D-пары. `linbo3.comsol_models.coupled.model` задаёт теги MPH,
  параметры материала и dataset. `analysis.py` сопоставляет решения по
  поляризации, векторной чётности и перекрытию комплексных полей.
- `studies.coupler_3d` проверяет продольную сетку на пилотном зазоре.
  `studies.coupler_3d_single` запускает только выбранные зазор,
  поляризацию и число слоёв. `studies.coupler_3d_compare` запускает TE
  и TM последовательно или строит сравнение из кэша.
- `linbo3.comsol_models.coupler_3d.inputs` восстанавливает пару 2D-мод
  по сдвигу поиска и номерам решений, проверяет SHA-256 поля, нормирует
  вход по мощности и находит веса возбуждения. `template.py` создаёт
  рабочую копию с пользовательскими портами и одним Frequency Domain.
  `solver.py` выставляет параметры, решает выбранную точку и выгружает
  поля. `diagnostics.py` строит графики по сохранённым данным.

## Кэш и координаты

- 2D-выгрузка связывает CSV с ID решений и комплексный NPZ через
  JSON-ссылку. `results/studies/coupled-modes/pairs.csv` задаёт пары
  для 3D, `candidates.csv` связывает их с исходными полями.
- 3D-ключ в `coupler_3d/cache.py` учитывает SHA-256 модели, таблицы
  SiO₂ и исходных 2D-полей, ID мод, геометрию, слои, `beta` и комплексные
  входные веса. Кэш сохраняется под блокировкой на случай. Отсутствие
  `settings.json` с совпавшим SHA-256 означает незавершённый результат.
- В 3D `z_um` — расстояние от входа. Направление относительно оси
  модели хранится в `direction`. Объёмные массивы в `sections.npz`
  идут в порядке `[z, y, x]`. `electric_squared_volume` хранит
  `|E|²`, `longitudinal_flux_w_m2` — знаковый продольный поток.
  `power_w` хранит левую и правую мощности в ваттах, интегрированные
  на отдельной контрольной сетке. Размер диагностической выборки
  не меняет ключ расчёта или сетку COMSOL.
- Старые NPZ содержат пять поперечных карт и кривые мощности.
  `coverage.csv` различает такие случаи, объёмную выгрузку и пропуски.
  Временные модели, карты и сгенерированные отчёты находятся в локальных
  каталогах, перечисленных в `.gitignore`.

## Проверка изменений

У команд сравнения и пилота `--dry-run` показывает задачи и кэш.
Запуск без `--solve` строит отчёт по готовым данным. Отдельный случай
с `--solve` использует закэшированный результат при совпадении ключа.
Команды 3D сохраняют графики через Agg.

```powershell
python -m unittest discover -s tests -p "test_*.py"
python -m studies.coupler_3d_compare --dry-run
```

Первое действие подходит для проверки кода без решателя. Второе
требует локальной MPH и готового 2D-отчёта.
